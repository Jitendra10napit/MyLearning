# System Design Interview Preparation Framework (2027)

If you're preparing for System Design interviews in 2027, save and follow this structured framework.

## 1. Requirements Gathering
- Identify functional and non-functional requirements.
- Estimate Daily Active Users (DAU) and Monthly Active Users (MAU).
- Understand the read-to-write ratio.
- Analyze usage patterns and traffic distribution.
- Identify scalability, availability, reliability, and performance expectations.

## 2. High-Level Design (HLD)
- Define the data model and database selection.
- Design APIs and communication contracts.
- Perform capacity planning and traffic estimation.
- Choose appropriate network protocols (HTTP, HTTPS, WebSockets, gRPC).
- Identify architectural style (Monolith, Microservices, Event-Driven Architecture).

## 3. Detailed Design (Deep Dive)
- Explain core components and their responsibilities.
- Evaluate architectural alternatives and trade-offs.
- Address concurrency, synchronization, and data consistency.
- Define caching, messaging, and database strategies.
- Discuss deployment architecture and infrastructure.

## 4. Design Optimization and Improvements
- Identify performance bottlenecks.
- Detect and eliminate single points of failure (SPOF).
- Improve scalability and fault tolerance.
- Implement caching, load balancing, and horizontal scaling.
- Consider monitoring, logging, and disaster recovery.

## 5. Conclusion and Discussion
- Summarize the overall architecture and key design decisions.
- Explain the trade-offs and assumptions.
- Highlight potential improvements and future enhancements.
- Discuss how the design can evolve as the system scales.

**Key takeaway:** A strong System Design interview is not just about drawing architecture diagrams. It is about understanding requirements, making informed trade-offs, explaining decisions, and designing scalable, reliable, and maintainable systems.
