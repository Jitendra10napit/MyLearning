# 1. Understanding the AI Ecosystem

## 1.1 What is Generative AI?

Generative AI is a branch of artificial intelligence that creates new content using trained models.

Examples:
- Generate C# code.
- Write SQL queries.
- Generate unit tests.
- Summarize technical documents.
- Answer questions from company documentation.
- Create architecture recommendations.

Common AI tools:

| Tool | Purpose |
|---|---|
| ChatGPT | General AI assistant |
| Claude | AI assistant for reasoning and coding |
| GitHub Copilot | AI coding assistant |
| Ollama | Runs supported LLMs locally |
| Azure OpenAI | Hosted model inference through Azure |

## 1.2 What is an LLM?

LLM stands for Large Language Model.

An LLM is trained on large amounts of data to understand and generate language.

Examples:
- GPT models
- Claude models
- Gemini models
- Llama models

### How an LLM works

1. Receives a user prompt.
2. Converts input into tokens.
3. Processes tokens through a neural network.
4. Uses attention mechanisms to understand relationships.
5. Predicts and generates output tokens.
6. Returns the generated response.

Important terminology:

| Term | Meaning |
|---|---|
| Token | Unit of text processed by the model |
| Context window | Input and conversation capacity |
| Transformer | Neural network architecture |
| Attention | Identifies relevant token relationships |
| Temperature | Controls generation variability |
| Hallucination | Incorrect or unsupported generated information |
| Inference | Running the trained model |
| Fine-tuning | Further training to adapt model behavior |

## 1.3 What is the difference between an LLM and an embedding model?

| LLM | Embedding model |
|---|---|
| Generates text | Generates vectors |
| Used for chat and reasoning | Used for semantic search |
| Example: GPT model | Example: text-embedding-3-small |
| Output: Natural language | Output: Numerical array |

Never store API keys directly in source code.

## 2.4 Implement an AI service

```csharp
using OpenAI.Chat;

public interface IAIChatService
{
    Task<string> AskAsync(string question);
}

public class OpenAIChatService : IAIChatService
{
    private readonly ChatClient _client;

    public OpenAIChatService(IConfiguration configuration)
    {
        var apiKey = configuration["OpenAI:ApiKey"];

        _client = new ChatClient(
            model: "gpt-4.1-mini",
            apiKey: apiKey);
    }

    public async Task<string> AskAsync(string question)
    {
        var response = await _client.CompleteChatAsync(
            question);

        return response.Value.Content[0].Text;
    }
}
```

Register dependency injection:

```csharp
builder.Services.AddScoped<
    IAIChatService,
    OpenAIChatService>();
```

Example controller:

```csharp
[ApiController]
[Route("api/ai")]
public class AIController : ControllerBase
{
    private readonly IAIChatService _aiService;

    public AIController(IAIChatService aiService)
    {
        _aiService = aiService;
    }

    [HttpPost("ask")]
    public async Task<IActionResult> Ask(
        [FromBody] string question)
    {
        var result = await _aiService.AskAsync(question);

        return Ok(new { answer = result });
    }
}
```

This is a basic demonstration. A production implementation should add input validation, authentication, exception handling, cancellation, rate limiting, logging, and model-specific configuration.

# 3. Embeddings and Semantic Search

## 3.1 What is an embedding?

An embedding converts text into a numerical vector representing semantic information.

Example:

Input:

"How do I recover my password?"

Output (illustrative):

```text
[0.21, -0.45, 0.82, 0.17, ...]
```

Two sentences with similar meanings generally produce vectors that are close in vector space.

## 3.2 OpenAI embedding models

| Model | Default dimensions | Usage |
|---|---:|---|
| text-embedding-3-small | 1536 | Cost-effective search and RAG |
| text-embedding-3-large | 3072 | Higher-quality retrieval |
| text-embedding-ada-002 | 1536 | Legacy applications |

## 3.3 Test using curl

```bash
curl https://api.openai.com/v1/embeddings \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -d '{
    "model": "text-embedding-3-small",
    "input": "Azure Service Bus supports asynchronous messaging."
  }'
```

The response contains an embedding array.

## 3.4 Implement embeddings in C#

```csharp
using OpenAI.Embeddings;

public class EmbeddingService
{
    private readonly EmbeddingClient _client;

    public EmbeddingService(IConfiguration configuration)
    {
        _client = new EmbeddingClient(
            model: "text-embedding-3-small",
            apiKey: configuration["OpenAI:ApiKey"]);
    }

    public async Task<float[]> GenerateAsync(string text)
    {
        var result = await _client.GenerateEmbeddingAsync(text);

        return result.Value.ToFloats().ToArray();
    }
}
```

## 3.5 What is cosine similarity?

Cosine similarity measures the directional similarity between vectors.

```text
Cosine Similarity =
(A dot B) / (Magnitude A * Magnitude B)
```

It is commonly used to identify semantically similar text.

## 3.6 What is a vector database?

A vector database stores embeddings and enables similarity search.

Examples:

- Azure AI Search
- PostgreSQL with pgvector
- Qdrant
- Pinecone
- FAISS

For enterprise Azure applications, Azure AI Search is a strong option because it supports vector and hybrid search.

# 4. RAG – Retrieval-Augmented Generation

## 4.1 What is RAG?

RAG retrieves relevant information from external knowledge sources and provides that information to an LLM before generating an answer.

It is useful when an LLM needs access to private or frequently changing company information.

## 4.2 Real-world example

Suppose your company has 5,000 technical documents.

A developer asks:

"How do we handle failed messages in Azure Service Bus?"

The system should:
1. Search relevant documents.
2. Retrieve retry-policy documentation.
3. Retrieve dead-letter queue documentation.
4. Send the relevant content to the LLM.
5. Generate an answer based on retrieved information.
6. Provide source references.

## 4.3 RAG architecture

### Document ingestion

```text
PDF / Word / Database
          |
          v
    Text Extraction
          |
          v
       Chunking
          |
          v
    Embedding Model
          |
          v
     Azure AI Search
```

### Query execution

```text
User Question
      |
      v
Generate Query Embedding
      |
      v
Azure AI Search
      |
      v
Retrieve Relevant Chunks
      |
      v
Construct Prompt
      |
      v
Azure OpenAI
      |
      v
Generate Answer
```

## 4.4 Important RAG concepts

| Concept | Explanation |
|---|---|
| Chunking | Splitting documents into smaller sections |
| Chunk overlap | Repeating a small portion between adjacent chunks |
| Embedding | Converting text into vectors |
| Vector search | Finding similar vector representations |
| Top-K | Retrieving the K most relevant results |
| Metadata filtering | Filtering by department, version, or access permissions |
| Hybrid search | Combining keyword and vector search |
| Reranking | Reordering retrieved documents based on relevance |

## 4.5 RAG vs fine-tuning

RAG is useful for providing external and frequently updated information.

Fine-tuning is useful for adapting a model's behavior to specialized tasks, style, or patterns.

They can also be combined.

## 5.3 Why use Azure Service Bus?

Document processing can take several seconds or minutes.

Instead of blocking an HTTP request, the API can enqueue a message and let a background worker process it.

Benefits:
- Decoupling.
- Asynchronous processing.
- Retry handling.
- Dead-letter queues.
- Better workload management.

Implement idempotency because message delivery can be repeated.

## 5.4 Why use Azure Functions?

Azure Functions execute event-driven background tasks.

Example:

When a document is uploaded to Blob Storage, a message triggers a Function that:
1. Reads the document.
2. Extracts text.
3. Splits it into chunks.
4. Generates embeddings.
5. Updates Azure AI Search.

# 6. AI Agents and Agentic AI

## 6.1 What is an AI Agent?

An AI agent uses an LLM to interpret objectives, select tools, observe results, and execute multiple steps toward a goal.

Example:

User:

"Investigate why Employee API returns HTTP 401."

Agent workflow:

1. Understand the issue.
2. Inspect approved application configuration.
3. Check JWT issuer and audience.
4. Review approved logs.
5. Identify a likely issue.
6. Suggest a fix.
7. Generate test cases.

An agent does not automatically have permission to execute every action. Tool permissions must be enforced by the application.

## 6.2 AI Agent Architecture

```text
          User Request
               |
               v
        Agent Orchestrator
               |
               v
              LLM
               |
        Decide Next Action
               |
        +------+------+
        |      |      |
        v      v      v
       RAG   Tools  Memory
        |      |      |
        +------+------+
               |
               v
        Observe Results
               |
               v
        Continue or Finish
               |
               v
          Final Answer
```

## 6.3 Agent components

| Component | Responsibility |
|---|---|
| LLM | Decision-making and response generation |
| Instructions | Defines role and boundaries |
| Tools | External operations |
| Memory/state | Maintains relevant context |
| Orchestrator | Coordinates execution |
| Guardrails | Enforces policies |
| Human approval | Controls sensitive actions |

## 6.4 Agent types

- Single-agent architecture.
- Multi-agent architecture.
- Supervisor-agent architecture.
- Sequential agents.
- Collaborative agents.

Start with a single agent unless multiple specialized agents provide measurable benefits.

# 7. Function Calling and Tool Integration

## 7.1 What is function calling?

Function calling allows an LLM to request execution of a function exposed by the application.

Example:

User:

"Find order 1052."

The model requests:

```json
{
  "name": "GetOrder",
  "arguments": {
    "orderId": 1052
  }
}
```

The application then:
1. Validates the arguments.
2. Checks authorization.
3. Invokes the C# service.
4. Returns the result to the model.
5. Generates the final answer.

The application controls actual execution.

## 7.2 Example C# tool

```csharp
public class OrderTools
{
    private readonly IOrderService _orderService;

    public OrderTools(IOrderService orderService)
    {
        _orderService = orderService;
    }

    public async Task<OrderDto?> GetOrderAsync(int orderId)
    {
        return await _orderService.GetByIdAsync(orderId);
    }
}
```

This is the application-side tool implementation. An agent framework or model-specific tool-calling adapter exposes the tool schema to the model.

# 9. MCP – Model Context Protocol

## 9.1 What is MCP?

MCP is an open protocol that standardizes how AI applications connect to external tools and data sources.

Example:

You want your AI assistant to access:
- GitHub.
- Azure DevOps.
- SQL Server.
- Technical documentation.

You can expose approved capabilities through MCP servers.

## 9.2 MCP architecture

```text
          AI Application
              |
              v
           MCP Host
              |
              v
           MCP Client
              |
          MCP Protocol
              |
       +------+------+
       |      |      |
       v      v      v
    GitHub  SQL DB  Azure DevOps
    Server  Server    Server
```

## 9.3 MCP components

| Component | Responsibility |
|---|---|
| MCP Host | Application coordinating MCP clients |
| MCP Client | Connects to MCP servers |
| MCP Server | Exposes tools and resources |
| Tools | Executable operations |
| Resources | Data and contextual information |
| Prompts | Reusable prompt templates |

## 9.4 MCP vs function calling

Function calling defines how a model requests an operation.

MCP standardizes how compatible applications discover and interact with external capabilities.

They complement each other.

## 9.5 MCP security

- Authenticate clients and servers.
- Authorize each operation.
- Validate input.
- Apply least privilege.
- Audit tool execution.
- Protect secrets.
- Require approval for sensitive operations.

# 10. Semantic Kernel and AI Orchestration in .NET

## 10.1 What is Semantic Kernel?

Semantic Kernel is a Microsoft framework for integrating AI models, plugins, and application functions.

It is relevant to .NET developers because it supports C# development and AI orchestration patterns.

Capabilities include:
- Chat completion.
- Prompt functions.
- Native plugins.
- Function calling.
- AI service integration.
- Agent workflows, depending on the framework version.

## 10.2 Why use Semantic Kernel?

Suppose you have these application services:

```text
OrderService
CustomerService
PaymentService
InventoryService
```

You can expose selected operations as plugins.

The AI application can select appropriate functions based on user requests.

Your business services remain independent of the LLM.

## 10.3 Framework comparison

| Framework | Primary purpose |
|---|---|
| Semantic Kernel | AI integration and orchestration, with .NET support |
| Microsoft.Extensions.AI | Common .NET abstractions for chat and embeddings |
| LangChain | LLM application development |
| LangGraph | Stateful agent workflow orchestration |
| MCP | Standardized tool and context integration |
| Ollama | Local model runtime |

# 12. Production AI Engineering Best Practices

## Security

- Never trust model-generated output as an authorization decision.
- Enforce document-level permissions before retrieval.
- Protect secrets with Key Vault.
- Treat retrieved documents as untrusted input.
- Restrict tool access using allowlists.
- Validate every tool argument.
- Apply human approval to sensitive operations.

## Performance

- Use appropriate model sizes.
- Limit unnecessary context.
- Cache suitable repeated results.
- Use asynchronous document ingestion.
- Tune vector indexes.
- Control concurrent model requests.

## Reliability

- Use bounded retries.
- Use exponential backoff and jitter.
- Implement timeouts.
- Handle rate limits.
- Use dead-letter queues.
- Make message processing idempotent.

## Monitoring

Track:
- Request latency.
- Token usage.
- Cost per request.
- Retrieval quality.
- Answer correctness.
- Tool execution failures.
- Model errors.
- User feedback.

## Evaluation

For RAG:
- Retrieval relevance.
- Recall.
- Answer groundedness.
- Citation correctness.

For agents:
- Task completion rate.
- Tool selection accuracy.
- Unauthorized action prevention.
- Execution cost.
- Workflow reliability.
