# Architect

## Definition

1. Responsible for making important decisions about how a project is designed and built.
2. Works closely with the delivery team to create the overall plan for how the project will work.
3. Focuses on the high-level technical design and functionality of the product.
4. Provides technical leadership to the development team and reviews the work from time to time to avoid risk.

## High-Level Design Areas

1. Component design
2. Data design
3. Interface design
4. Security design
5. Performance design
6. Others (scalability, availability, deployment, cost)

## Responsibilities

1. Understands the architecture and system requirements, as well as the functionality and performance of the other products in the system.
2. Defines the top-level system design of the product.
3. Liaises closely with Design Authorities and Lead Designers assigned to projects in the same architecture.
4. Provides constant and careful technical leadership and oversight of projects.
5. Assists development teams in assessing and avoiding risk.
6. Defines the development tools, practices and technologies used in the projects.
7. Develops relationships with the NICE product management team and major technical partners.
8. Reviews the product design with the Design Authority, Systems Engineer and Developers.

---

## The Enterprise Architect (EA)

- Owns the product and software architecture within their domain.
- Works with the PO and PM to ensure architectural items are included in the domain roadmap.
- Defines the tools and technologies within their domain.
- Ensures a consistent approach with other domain teams by attending the solution architecture forum.
- Works within the architectural strategy defined by the Solution Architecture Team.
- Is responsible for ensuring good code quality within their domain.
- Works with the Test Lead to define the test strategy for their domain.
- Promotes innovation within their domain team.
- Is often the Security Architect for their domain.

# Day-to-Day Responsibilities

## 1. Collaboration with PO & PM

- Prioritize architectural items (infrastructure, security, technology upgrades).
- Align the roadmap with technical feasibility.
- Identify risks and dependencies early.

## 2. Architecture Ownership

- Own the software architecture of the application/domain.
- Ensure scalability, reliability and maintainability.
- Create and maintain architectural artefacts (high-level design, diagrams).

## 3. High-Level Feature Design

- Break down features into high-level design.
- Identify dependencies, integrations, tools and components.
- Provide implementation guidance to the development team.

## 4. Tools, Technologies & Guidelines

- Define the tech stack, frameworks and libraries.
- Set coding standards and architecture guidelines.
- Ensure consistency across teams and with the Solution Architect's direction.

## 5. Code Quality & Reviews

- Oversee the code review process.
- Enforce clean code, design patterns and best practices.
- Ensure the quality and maintainability of the codebase.

## 6. Test Strategy Collaboration

- Work with the Test Lead to define the L1, L2 and L3 testing strategy.
- Ensure test coverage aligns with the architecture.
- Promote a shift-left testing mindset.

## 7. Security Responsibilities

- Act as the Security Architect for the team.
- Implement and enforce secure coding practices.
- Run static code scans (SAST) and periodic Black Duck scans (SCA).
- Enable GitHub Advanced Security for early vulnerability detection.

## 8. Cross-Domain Alignment

- Ensure architectural consistency across domains.
- Work with the Solution Architect on governance and standards.
